## 结论与证据

- 原 271 条＋新 48 条＝319 条；新句与原语料无重复。旧 271 条分词无变化，全部保持原文、顺序，确认记录序列化后可恢复。该检查不等于意思全部正确。
- 新句在执行前冻结：SHA-256 `3a324c76335f66fe96478d3e264df499327cfbc0bd9b855e55dfac465d5812ed`，文件保持不变。47 条有粒度标注的句子中 37 条满足约束，107/118 子约束满足；1 条仅图片检查。不是专业人士标注的金标准，也不是整体语义准确率。
- 冻结规则发现 2 处姓名误配。视觉复核新增“刹车坏了”的评价手势图问题，另有“放凉”被拆成放置动作的风险。新增观察独立记录，不反改原参考分数。
- Web 真实本机候选构建运行 48 句，分词均与核心一致；其中 2 句因 UI 默认图库包含 `/symbols/arasaac/we.png` 而基线没有此图。来源文件为 `src/api/corePicSeePal.json`，不能将此类图库差异计作错误分词。
- 小程序实际适配器：有 Intl.Segmenter 时 48 句分词一致；默认“要”有 1 处图卡 ID 差异（pi-home-want 与 B1AEEA5pm5tb）。打包 PNG 与 Web SVG 路径本来不同，未将其全部判成错误。
- 无 Intl.Segmenter 回退：23/48 句切法不同，粒度约束 28/47 满足，冻结规则命中 3 次姓名片段错图。该运行方式模拟缺少运行时能力，不等于某台手机一定如此。
- 小程序两种分词方式共 96 条记录确认文字后均可序列化及离线恢复。4 句配置合成人名个人图库后可完整匹配，另一档案不继承；不读取真实个人图库或照片。
- 今晚／回家／吃饭：新句内 10 次，默认 0 张；使用既有公共图源抓取及显式确认记录后 10 次带图恢复。加原有语料共 59 次。只表示确认后的目标覆盖，不是自动补图准确率。
- 上一轮浏览器完整流程已补证通过：停车场、请帮忙、刹车候选筛选、确认、图片字节缓存，断网关闭标签页后新开，3 张图能加载；未测试浏览器进程重启。见[上一轮回执](../../../outputs/tuyujia-common-sentences-followup-20261018/../tuyujia-context-candidate-repair-20261018/browser-receipt.json)。
- 候选构建对应 4962 个来源文件哈希仍一致。本轮浏览器测试的是本机候选，不是已部署线上版本。

## 待修复顺序

1. 人名后的时间词、并列关系和状语：小岚明天、小林和小岚一起；继续复用个人图库和姓名词义保护。
2. 物体损坏、降温语境：“刹车坏了”不能只配评价手势；“放凉”应按完整动作处理。
3. 回退分词词典覆盖：牙刷、筷子、空调、开关、阿姨；优先复用现有词典和两端一致的词条来源。
4. 停车位、盖被子、七点等完整单位；三次／一杯／十分钟需区分合理组合与过细切分。
5. 测试应显式区分核心 advanced 图库、实际 Web 图库、小程序打包图库；保留素材来源与图卡 ID，避免把打包路径不同算作错误。
