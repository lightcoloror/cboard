## 已复现的问题与实际修复

1. **路径不等于图片可用**：修改前受控存储故障基线 5 项失败，返回路径但缺失/损坏文件可被旧保存流程接受。它证明该路径的故障处理缺口，不证明用户图片普遍丢失。原始结果保留在 `baseline-valid-fixture.log`。
2. **旧快照覆盖新图片**：生产浏览器流程发现已采用的新图片被 `persistedOutput` 的旧图片覆盖。复用原快照构造流程，只更新当前项图片/来源，保留身份、重复顺序、背景等字段；新增共用回归。
3. **小程序本机路径形式**：开发者工具 `saveFile` 返回 `http://store/...`，实际为本机存储。现已支持该形式，但仍须原生文件读取和解码通过。原生 `readFile ... not found` 明确归为缺失；权限/超时等仍是检查失败，不推定已删除。
4. **失败后误删旧图风险**：取消补图或记录失败不再清理可能仍被历史/草稿引用的旧文件。不进行全库垃圾清理；隔离开发者工具内可能保留本轮未引用合成图片，绝不自动采用。
5. **旧回调验收同步**：保留首次回调测试失败记录；补齐实际新增依赖，并将旧“保存失败即删图”断言调整为本轮明确要求的保留、无重复下载重试及隐私清理保护。仍运行产品源码提取的真实回调，不复制另一套业务逻辑；`mini-posttest-final.log` 共107项通过，包含22项补图回调。
