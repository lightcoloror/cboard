# 图语家现场反馈复查

记录：2026-10-22，Codex。范围：当前正式网页的隔离浏览器行为及对应本地源码。未修改产品、未发布、未访问真实账户、未使用私人照片或付费模型。

## 结论

顶部已选图片栏的清空、退格、连续撤销当前可以恢复。界面清晰度问题仍有具体表现；本轮发现新加入的保存提示和图片修复控件存在布局与状态文案问题。不能把顶部撤销通过推广为文件夹、图库卡片及所有删除对象都已安全。

## 当前已验证可用

- 中文浏览器首次进入，无需登录即可选择默认图卡。
- 首次选图会展开患者表达工作区，出现第一次使用引导；完成引导后可继续操作。不是“选图后完全没有下一步”。
- 选择“是、不”→清空→撤销，恢复两张图及原顺序。
- 同一表达→退格→清空→连续两次撤销，恢复“是、不”及顺序。
- “食物”分类可以进入，原顶部表达保留；分类有文件夹外形，不能认定完全没有层级标识。

## 当前问题

### 1. 平板宽度下修复和排序按钮超出视口（优先）

步骤：中文新浏览器→选择“是、不”→完成首次引导→进入食物→视口768×1024。

结果：重新选择本机图片、保留文字、左移、右移、删除按钮伸出右边界。测量中视口和文档滚动宽度都是768，部分按钮右边界达到约1315，不能靠普通横向页面滚动完整看到。

证据：[截图](08-tablet.png)、[位置与图片缓存测量](layout-cache-metrics.json)。

源码关联：`ExpressionLoopPanel.component.js` 把 ImageRepairControls 放进 sequenceActions；CSS 的 sequenceActions 使用 `flex: 0 0 auto`，且 sequenceItem 的换行断点仅在600px以下。新控件比原来的左右移和删除明显更宽。

建议：复用当前布局，按实际容器宽度换行；状态、修复入口和排序动作分行，验证768/1024/桌面宽度。无需重建编辑器。

### 2. 保存提示占用整列，主要操作被挤到右侧（优先，与上项相关）

步骤同上，桌面1400px亦可见。

结果：“已保存到本机”单独占一整列，下面大片空白；候选句和常用短句被挤向右侧。768px时表达区只剩约半屏。

证据：[清空后界面](04-cleared.png)、[平板界面](08-tablet.png)。

源码关联：ExpressionLoopPanel在 `.CommunicationSupportPanel__content` 下直接加入保存提示div；该容器为 `repeat(auto-fit, minmax(320px, 1fr))` 网格。提示被当作与表达工作区同级的一整栏。

建议：提示跨栏或放在表达区内部，保留真实保存状态与重试能力。

### 3. 尚无离线缓存被提示为“本机图片缺失”（需区分状态）

结果：“是、不”图片实际已读取显示，naturalWidth/naturalHeight均850；但Cache API尚未命中，界面显示“本机图片缺失，请重新选择或保留文字”，并提示“原素材无法可靠定位”。点击重新检查仍如此。

证据：[测量](layout-cache-metrics.json)、[检查后页面](10-after-cache-check.json)。当时Service Worker尚未控制页面，因此这里证明的是新浏览器启动阶段状态提示有歧义，不证明离线预备完成后图片也丢失。

源码关联：`browserImageVerification.js` 中 packaged 引用在Cache API未命中时直接返回missing；组件立即展示修复动作。缺少“尚未缓存/尚未完成离线准备”和“曾保存文件现已丢失”的区分。

建议：继续保持“不自动下载”的边界；对尚未完成缓存核验的默认公开资源给出准确状态，避免让用户误以为需要重选照片。不能为了消除提示直接标记离线可用。

### 4. 撤销存在，但触屏上含义仍不够明确

清空后出现弯箭头撤销图标，但没有持续可见的“撤销清空”文字。顶部退格、清空的辅助标签在中文环境仍是硬编码的Backspace/Clear；两者没有文字说明。源码与当前DOM一致。

证据：[清空后截图](04-cleared.png)、[清空后按钮状态](04-cleared.json)。源码：SymbolOutput、ClearButton、BackspaceButton。

这是可发现性与本地化缺口，不是本轮已复现撤销功能失效。建议沿用CBoard图标，加简短中文标签和删除后状态提示。

### 5. 分类名称没有贯通到表达区

进入食物后，黑色导航栏显示“食物”，表达区却显示“当前板：r1-FTvnvaW”；首页也显示CBOARD CLASSIC HOME。机器ID不能帮助用户理解当前位置。

证据：[食物页](07-food.json)。源码直接渲染activeBoardId。建议复用已有板名称/父级路径，保留已有返回能力；是否首次就能分清文件夹仍需真人体验。

## 验收边界

- 浏览器使用独立临时配置目录，退出时实际关闭进程；本轮不宣称完成离线关闭重开验收。
- 默认语言已显式设为zh-CN。初轮英文浏览器显示英文分类是语言设置影响，未作为中文标签缺失上报。
- 复用现有Playwright生产页面及语音替身；所有API和跨域请求被拦截。因此不据此判断真实登录、后端加载、在线AI或真实音频成败。
- 请求日志无私人标记或AI/扣费请求，未触及真实账户。无页面异常；对应日志见production-navigation-audit系列JSON。
- 中途测试曾因英文/中文选择器及未关闭首次引导而超时；属于验收脚本适配过程，不能报告成产品崩溃。
- 本轮未运行小程序、手机/iPad真机、真实扬声器、图库/文件夹删除或收藏删除全流程。现场误删对象仍未精确确定。
- 这是一条含多个检查点的浏览器场景通过，不是整个产品所有功能已通过。

## 建议顺序

1. 修复保存提示占列和图片修复区域溢出。
2. 区分缓存未就绪、未核验和实际缺失；保留本地核验及人工采用。
3. 补齐删除/撤销文字及中文辅助标签，用真实名称显示分类。
4. 再分别补测图库卡片、文件夹、收藏的删除边界，不能把顶部输出栏撤销当作通用回收站。
