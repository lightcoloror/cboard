本轮主机为 Windows 10.0.26100.0。安全 loopback 页面确实暴露 ServiceWorker、CacheStorage、IndexedDB，worker 也曾处于 activated/controller=true，但这些状态不能替代缓存读回与离线载入验证。

[官方浏览器文档](https://playwright.dev/docs/browsers)要求 Playwright 使用匹配浏览器；[安装文档](https://playwright.dev/docs/intro)列明 Windows WebKit 支持。上游 [#42775](https://github.com/microsoft/playwright/issues/42775)记录较新 Playwright/Linux 下相同离线模拟错误，仅作为机制线索，不能证明本次 Windows 失败的全部根因。未升级项目或浏览器版本来改变验收对象。

重要证据入口：`summary.json` 给出精确最新证据文件映射；`tested-input-identities.json` 保存当前测试输入哈希；`diagnostic-final-report.json` 为最终四个分层检查的执行报告。其 4 passed 表示检查脚本完成，包含记录失败的离线/缓存探针，**不等于四项产品离线能力通过**。`layered-report.json` 保留此前 4 passed / 2 failed；其中大字号首轮因等待尚未出现的撤销按钮超时，已修正测试定位并在最终报告通过。原生缓存检查失败仍保留，未用响应注入结果覆盖。`repair-gallery-report.json` 保留最初离线重启失败证据。历史 `local-photo-offline.png` 是复用旧脚本留下的命名，实际在线重启图请引用 `local-photo-online-restart.png`。

可复跑入口：`run-webkit.ps1`（整个套件包含保留的原生缓存失败检查，预计不会全绿）。`prepare-harness.cjs` 与 `prepare-decoder.cjs` 仅为本轮生成适配副本的来源记录；复跑不应重新执行它们。

实际浏览器均使用本目录新建合成资料，关闭与不同 PID 已记录；服务器只绑定 `127.0.0.1:4208`，由 Playwright 关闭。生产应用测试拦截外部和 `/api/` 请求；最小无脚本缓存对照只有 `/manifest.json` 一个请求。未使用私人数据、真实模型、扣费、真实用户存储。语音沿用既有确定性 mock，不证明真实扬声器或语音服务。未测试真实 iPhone/iPad、iOS Safari、微信 WebView、系统杀进程、真实系统大字号或真实设备存储回收。
