# 续验：新版 WebKit 与语言 fallback 修复

2026-10-23，Codex（GPT-6 系列，精确运行模型未独立核实）。本文件补充此前《验收结论.md》，旧日志与失败证据均保留。

复用了 Codex 已存在的官方依赖包 Playwright **1.62.1**，路径来自 `load_workspace_dependencies`。没有安装 npm 依赖或更改项目 package/lock。仅将对应 **WebKit 26.5 / revision 2336**、Winldd 1007、FFmpeg 1011 浏览器配套组件下载到 `browser-cache-162/`，没有系统依赖、全局配置、服务或代理变更。

新运行时最小缓存对照的四种情况全部写读成功：持久 context/临时 context × 路由拦截开/关。旧 1.50.0 / WebKit 18.2 组合的空缓存现象不能归责为产品代码。证据为 `local-new-runtime-cache.json`。

在同一生产候选 `.local-build-20261023-targeted-ui-v2` 上，新运行时实际写入 **1027 条生产预缓存**，`/index.html` 可从 Cache API 读回。关闭本轮自有 `127.0.0.1:4208` 静态服务器后：

- 同页重载成功，导航 `fromServiceWorker=true`。
- 同 context 新页成功，导航 `fromServiceWorker=true`。
- 关闭并启动独立浏览器进程后仍成功，导航 `fromServiceWorker=true`，显示图片解码通过。
- 通过产品 UI 保存的合成人物照片在新进程、原站关闭情况下恢复，数据与 40×40 解码尺寸完全一致。

这证明了**原站不可达条件下的真实缓存恢复**；不是操作系统整体断网、iOS 或真机生命周期证明。`context.setOffline(true)` 仍报 WebKit internal error，其证据与[上游已记录的模拟问题](https://github.com/microsoft/playwright/issues/42775)一致，但环境/版本不同，不能直接等同产品离线失败。

运行上述路径时还观察到产品页面错误 `t.langs.sort is not a function`；不使用 setOffline 的原站关闭对照也能复现，所以未忽略、未将整项报告改成通过。只读定位到 `LanguageProvider.container.js:65`：资源导入失败时 `setLangs(platformLangs.push(DEFAULT_LANG))` 传的是数组长度；reducer 随后对数字调用 `.sort()`。

按新增明确授权，仅修改产品 `src/providers/LanguageProvider/LanguageProvider.container.js` 和其现有 `__tests__/LanguageProvider.test.js`：传入新数组 `[...platformLangs, DEFAULT_LANG]`，同时保留原 props 数组。新增最小失败回归先证实旧代码实际传入 `2`；修复后三个现有语言 suites **8/8 通过**，`git diff --check` 通过。

证据：`language-fallback-before.log`、`language-fallback-after.log`。**尚未在统一重建后的生产包复验此修复**；本子任务未另起构建。旧包两份现代运行时端到端报告都因 pageerror 正确保持失败状态，不能称全绿。
